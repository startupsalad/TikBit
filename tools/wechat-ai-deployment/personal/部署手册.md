# [个人微信接入AI] 部署手册 · 公开版

> **这份手册是什么**：教你（或你的 Claude Code）把**个人微信**接入一个跑在**自己的电脑或自己的云服务器**上的 Claude Code，实现"在微信里跟一个机器人好友聊天，背后是 Claude Code + 你自己的知识库"。支持文字、语音、图片、文生图、图生图、发文件、多人共用同一知识库且记忆互不干扰。
>
> **怎么用**：把这份手册（连同附录的两个代码文件）整份发给你自己的 Claude Code，说一句"照着这份手册帮我部署"，它就能在你的机器上装出一套同样的功能。
>
> **谁适合**：想让个人微信连上 Claude Code 的任何人。**最低门槛只要一台一直开着的电脑**（Mac/Windows/Linux 都行），不需要云服务器、不需要公网 IP。
>
> **🔑 你需要自备一把大模型 API 密钥**（用于识图和对话）：本方案不附带密钥。推荐到 **TikBit.ai** 注册申请一把自己的密钥（支持 Claude 模型、支持识图、支持生图，国内直连稳定），拿到 `base_url` 和 `sk-` 开头的 key 后填进环境变量即可（见前置条件第 5 条 + 环境变量速查）。也可用官方 Anthropic key 或其它支持 Claude 模型的中转。
>
> 版本：v1·公开版（2026-06-24）

## 一、核心原理（先懂这个，少走半天弯路）

### 1.1 个人微信接 AI，唯一安全的路：微信官方 iLink Bot API

**关键认知**：个人微信**没有**传统意义的开放机器人接口。市面上多数"个人微信机器人"方案（wechaty、各种 iPad 协议网关）都是**第三方破解协议**，有**真实封号风险**，腾讯随时打击、库随时失效。

**但本方案不一样**——用的是微信官方近期推出的 **iLink Bot API（ClawBot）**：

- **官方通道**，接口地址 `https://ilinkai.weixin.qq.com`，腾讯自己提供，**零封号风险**（和企业微信一个安全级别）
- **不需要在服务器登录任何微信号**：你的微信永远在你手机里。扫码只是"授权创建一个官方机器人"，类似扫码登录网页版的授权动作
- **不需要公网 IP**：机器人通过**长轮询**主动连微信服务器拉消息，服务器只需能访问外网
- 你在手机上聊天的对象，是这个**官方机器人**，不是某个被登录的私人号

> ⚠️ **前提**：这是微信较新的功能，对手机微信版本有要求（见前置条件）。可能有灰度，部署前先用 `ccwx-login.js` 试拉一次二维码，能出码就说明接口对你开放。

### 1.2 为什么不用现成插件 cc-weixin，而是自建桥接？

社区有个开源插件 `cc-weixin`，原理也是官方 iLink API。但它依赖 Claude Code 的 **"channels（通道）"** 功能，而该功能在较新版本的 Claude Code 里**已被官方关闭**（启动会报 `Channels are not currently available`、`--dangerously-load-development-channels ignored`）。

所以本方案**绕开插件**，自己写一个轻量桥接 `ccwx.js`：长轮询收消息 → 调用 headless `claude -p` → 把回复发回微信。**不依赖任何内测功能，更稳、可控、易维护**。

### 1.3 整体架构

```
你手机微信 ──私聊──→ 微信官方服务器(ilinkai.weixin.qq.com)
                          ↑ 长轮询 getupdates 拉消息
                   ccwx.js 桥接(跑在云服务器/本地电脑)
                          ↓ spawn: claude -p
                   Claude Code(读你的知识库/skill)
                          ↑ 回复(含 @IMG/@FILE 标记)
                   ccwx.js 解析 → 上传CDN → 发回微信
```

## 二、前置条件（缺一不可，先逐项确认）

| # | 条件 | 怎么满足 / 怎么验证 |
|---|------|------|
| 1 | **手机微信版本够新** | iOS ≥ 8.0.70 / 安卓 ≥ 8.0.69 / Mac ≥ 4.1.8.67。看「我→设置→关于微信」。不够先升级微信 |
| 2 | **iLink 接口对你开放** | 部署机器上跑 `ccwx-login.js`，能拉出二维码链接=通过（接口可能有灰度） |
| 3 | **一台常开的机器** | 云服务器 或 一直开机的本地电脑（Mac/Win/Linux）。机器关机=机器人离线 |
| 4 | **Node.js ≥ 20** | `node --version`。本桥接用到全局 fetch/crypto，必须 Node 20+ |
| 5 | **Claude Code 已装好并能用** | 终端 `claude --version` 有输出；且已配好模型（`ANTHROPIC_BASE_URL` / `ANTHROPIC_AUTH_TOKEN` / `ANTHROPIC_MODEL` 环境变量，或官方登录）。识图功能依赖这几个环境变量 |
| 6 | **一把大模型 API 密钥（自备）** | 没有就去 **TikBit.ai** 注册申请一把（支持 Claude 模型+识图+生图）。拿到 `base_url`（形如 `https://tikbit.ai`）和 `sk-` 开头的 key，填进上面第 5 条的环境变量。本手册不附带任何密钥 |
| 7 | **tmux（保活用）** | 让桥接常驻后台、关掉终端也不停。`tmux -V` 验证；没有就 `apt install tmux` / `brew install tmux` |

> **云端 vs 本地，怎么选**：
> - **云服务器**：人在外面、电脑关机也能用，适合团队共用、长期在线。需要会基本的 SSH/Docker。
> - **本地电脑**：最简单，无需公网、无需 Docker，机器人能直接操作你本地的文件和项目。代价是电脑得一直开着。
> 两者部署步骤几乎一样，差别只在"在哪台机器上跑"。

## 三、安装 SOP（一步步照做）

> 下面用 `$WORK` 代表放桥接代码的目录（如 `~/ccwx`），`$KB` 代表你想让机器人读写的知识库目录（如 `~/我的知识库`，本地电脑也可以就是某个项目文件夹）。

### 步骤 1：准备目录和代码

```bash
mkdir -p ~/ccwx && cd ~/ccwx
# 把附录的两个文件存进来：ccwx.js（桥接主程序）、ccwx-login.js（扫码登录）
# （Claude Code 可直接根据本手册附录把这两个文件写出来）
```

### 步骤 2：装依赖（tmux）

```bash
# Linux: apt install -y tmux    Mac: brew install tmux
tmux -V   # 出版本号即可
```

### 步骤 3：扫码连接微信（生成机器人）

```bash
cd ~/ccwx
CCWX_STATE_DIR=~/ccwx/state-me node ccwx-login.js
```

- 终端会打印一个二维码**链接**。把链接转成二维码图片（任意"链接转二维码"工具，或粘贴到浏览器），**用手机微信扫一扫**
- 手机上点**确认连接机器人**，再**随便发一句话**
- 看到 `✅ 连接成功！` 即可。凭证存进了 `~/ccwx/state-me/`，并已把你的微信自动加入白名单（本人发消息免配对码）

### 步骤 4：启动桥接（常驻后台）

```bash
tmux new-session -d -s ccwx-me \
  "CCWX_STATE_DIR=~/ccwx/state-me CCWX_BOT_NAME=me CCWX_CWD=$KB node ~/ccwx/ccwx.js 2>&1 | tee ~/ccwx/ccwx-me.log"
```

- `CCWX_CWD=$KB`：机器人的"工作目录"=你的知识库。Claude 会读这里的 `CLAUDE.md`、文件、skill
- 看日志确认启动：`cat ~/ccwx/ccwx-me.log`，出现 `桥接启动` 即成功

### 步骤 5：手机微信里测试

给机器人发「**你好，你能做什么？**」→ 收到正经回复 = **整条链路打通**。再测发语音、发图片、发「新对话」。

## 四、多人共用同一知识库（记忆隔离的关键）

如果想让多个人（你 + 同事/朋友）各自用自己的微信连同一套系统，**共享知识库但聊天记忆互不干扰**，关键是给每个人三样独立的东西：

| 环境变量 | 作用 | 每人怎么设 |
|---------|------|-----------|
| `CCWX_STATE_DIR` | 存各自的 token/白名单/会话 | 各给一个独立目录，如 `state-me`、`state-friend` |
| `CCWX_CWD` | Claude 的工作目录 = **记忆隔离钥匙** | 各给一个**真实不同的目录**（见下方铁律） |
| `CCWX_BOT_NAME` | 日志里区分谁是谁 | `me` / `friend` 任意 |

**为每个新成员重复"步骤 3 + 步骤 4"即可**，换掉这三个变量。例如给朋友加一个：

```bash
# 朋友扫他自己的码
CCWX_STATE_DIR=~/ccwx/state-friend node ccwx-login.js
# 朋友的工作目录用知识库下的一个真实子目录(记忆隔离) → 但仍能向上读到知识库的 CLAUDE.md
mkdir -p $KB/.bots/friend
tmux new-session -d -s ccwx-friend \
  "CCWX_STATE_DIR=~/ccwx/state-friend CCWX_BOT_NAME=friend CCWX_CWD=$KB/.bots/friend node ~/ccwx/ccwx.js 2>&1 | tee ~/ccwx/ccwx-friend.log"
```

> ### 🩸 记忆隔离铁律（血泪坑，务必照做）
> Claude Code 的"记忆"是**按工作目录（cwd）的真实路径**存的。要让两个人记忆分家：
> - ✅ **必须用真实的不同目录**（如主人用 `$KB`，朋友用 `$KB/.bots/friend`）。Claude 读 `CLAUDE.md` 会**向上层目录找**，所以子目录照样能读到知识库根的 `CLAUDE.md` 和所有文件——**知识库共享、记忆隔离**两全。
> - ❌ **不能用软链接**来造"不同目录"：进程会把软链接解析回真实路径，记忆还是会落到同一个地方、串味。
> - 如果不在乎隔离、就想所有人共用一套记忆，那所有人 `CCWX_CWD` 都指向 `$KB` 即可。

**共享与隔离一览**：知识库文件 / skill / 待修复清单 = **共享**（一处改动大家可见）；聊天上下文 / Claude记忆 = **隔离**（各人独立）。

## 五、支持的功能（机器人能干什么）

| 功能 | 用法 | 说明 |
|------|------|------|
| 文字对话 | 直接发文字 | 多轮上下文，每人独立会话 |
| 语音 | 发微信语音 | 微信自动转文字，机器人能听懂 |
| 图片识别 | 发图片+问题 | 直连视觉API识图（不走 claude Read，避免读图不准） |
| 文生图 | 「画一张…」 | Claude 调你配的生图工具 |
| 图生图 | 发图+「按这张改成…」 | 原图自动落盘，路径喂给 Claude 做参考编辑 |
| 发图给你 | — | Claude 回复里写 `@IMG:绝对路径`，桥接自动上传发送 |
| 发文件给你 | — | Claude 回复里写 `@FILE:绝对路径`，发 PDF/Word/Excel/PPT 等 |
| 引用消息 | 引用某条图/文字再追问 | 引用的图会被下载识别、引用的文字会带上 |
| 开启新对话 | 发「新对话/重新开始/重置/清空上下文」 | 秒清当前上下文，重新开始 |
| 停止任务 | 发「停/停止/暂停/中断」 | 中断正在跑的任务，秒回 |
| 自我介绍 | 问「你能做什么」 | 据实口语介绍能力，不暴露技术细节 |

> **它怎么知道这些标记/能力？** 桥接在每条消息前注入一段"系统提示前缀"，告诉 Claude：①这是个人微信通道 ②发图用 `@IMG:`、发文件用 `@FILE:` ③安全红线（不暴露账号密码路径/不提内部系统名）④被问能力时怎么介绍。**这是桥接能力生效的前提——接收端代码 + 发送端 Claude 知道怎么触发，缺一不可。**

## 七、踩坑速查（结论先行，都是实战踩出来的）

- **`Channels are not currently available` / `--dangerously-load-development-channels ignored`**：这是用现成插件 cc-weixin 才会撞的墙——它依赖的 channels 功能被官方关了。**本方案不用插件、不会遇到**。如果你看到它，说明你在试插件路线，放弃，改用本手册的自建桥接。

- **🩸 桥接启动即崩、报 `Cannot read properties of undefined (reading 'CCWX_STATE_DIR')`**：变量名遮蔽全局对象。绝对**不要**把函数命名为 `process`（Node 全局对象，`process.env` 靠它）——函数声明会提升、覆盖全局，导致 `process.env` 变 undefined。本手册附录代码已把队列任务函数命名为 `runTask` 规避。`node --check` 查不出这种运行时遮蔽，只有真跑才暴露。

- **🩸 多人记忆串味（你存的"7"被对方覆盖成"99"）**：根因是两个机器人 `CCWX_CWD` 指向同一目录 → 共享 Claude 记忆区。**正解：每人一个真实不同的 cwd**（见第四章铁律）。注意软链接没用（会解析回真实路径）。

- **🩸 图生图说"拿不到原图" / 回复答非所问、慢一拍**：两个独立 bug，本手册附录代码已修：
  - "拿不到原图"：图片其实已落盘，但要**把真实路径喂给 Claude**（前缀里告知），它才会用 `--reference` 做图生图。
  - "慢一拍/答非所问"：微信把"图片"和"文字指令"**分成两条消息**发来。必须做**图文合并**（图先暂存、等下条文字指令到了一起处理）+ **串行队列**（一条做完再做下条）。附录代码已含这两套机制。

- **🩸 机器人乱提"企业微信/网盘/密码"等内部信息**：如果你的知识库 `CLAUDE.md` 里有这类内容，Claude 读到会照搬甚至泄露。**正解**：桥接前缀里设了"安全红线"，且**每条消息都注入**（只在首条注入会被后续轮次淹没）。客户部署时知识库别放敏感凭证。

- **图片识别用 claude 的 Read 会瞎编**：claude Read 读图不准。本方案**直连视觉 API**（`describeImage`）识图，把文字描述喂给 Claude，绝不让 claude 自己 Read 图。

- **长耗时任务（生图、做带图 PPT）**：单任务超时默认 15 分钟。生图多步任务、每页配图的 PPT 别把 `CCWX_TIMEOUT_MS` 调太短，否则"假超时"（东西其实做好了，只是没来得及发出来）。配图页数也要控量（建议 ≤8 张图），太多连 15 分钟都不够。

- **机器人离线了**：检查 ①部署机器是否关机/断网 ②tmux 会话是否还在（`tmux ls`）③看日志 `cat ~/ccwx/ccwx-*.log` 尾部有无报错。会话过期会自动暂停30秒重试。

## 附录 A：完整代码

> 把以下两个文件**原样**保存到 `~/ccwx/` 下。两个文件**自包含、无外部依赖**，只需 Node 20+ 和一个能用的 `claude` 命令。

### A-1：`ccwx-login.js`（扫码登录，约 40 行）

```javascript
// ccwx-login.js — 扫码连接微信机器人，把凭证存进 CCWX_STATE_DIR/account.json
// 用法：CCWX_STATE_DIR=/path/to/state node ccwx-login.js
// 运行后终端会打印一个二维码链接，用手机微信扫它、点确认，再随便发一句话即可。
const fs = require('fs');
const path = require('path');
const BASE = 'https://ilinkai.weixin.qq.com';
const STATE_DIR = process.env.CCWX_STATE_DIR || path.join(process.env.HOME || '.', '.ccwx');
if (!fs.existsSync(STATE_DIR)) fs.mkdirSync(STATE_DIR, { recursive: true });

(async () => {
  // 1) 拉二维码
  let r = await fetch(`${BASE}/ilink/bot/get_bot_qrcode?bot_type=3`);
  let d = await r.json();
  console.log('\n请用手机微信「扫一扫」扫描下面这个链接生成的二维码（可粘贴到浏览器显示二维码，或用工具把链接转成二维码）：\n');
  console.log('  ' + d.qrcode_img_content + '\n');
  console.log('扫码后在手机上点「确认」，脚本会自动继续…\n');
  let qid = d.qrcode;

  // 2) 轮询扫码状态（最多5分钟，过期自动刷新）
  let token, userId, baseUrl = BASE;
  const deadline = Date.now() + 300000;
  while (Date.now() < deadline) {
    const sr = await fetch(`${BASE}/ilink/bot/get_qrcode_status?qrcode=${encodeURIComponent(qid)}`, { headers: { 'iLink-App-ClientVersion': '1' } });
    const sd = await sr.json();
    if (sd.status === 'confirmed') { token = sd.bot_token; userId = sd.ilink_user_id; baseUrl = sd.baseurl || BASE; break; }
    if (sd.status === 'scaned') console.log('已扫码，等你在手机上点确认…');
    if (sd.status === 'expired') { console.log('二维码过期，刷新中…'); const rr = await fetch(`${BASE}/ilink/bot/get_bot_qrcode?bot_type=3`); const rd = await rr.json(); qid = rd.qrcode; console.log('\n新二维码链接：\n  ' + rd.qrcode_img_content + '\n'); }
    await new Promise(s => setTimeout(s, 2000));
  }
  if (!token) { console.log('❌ 超时未完成扫码'); process.exit(1); }

  // 3) 存凭证 + 把扫码人加进白名单（这样本人发消息免配对码）

async function dispatch(msg) {

      if (resp.ret && resp.ret !== 0) throw new Error('getUpdates ret=' + resp.ret + ' ' + (resp.errmsg || ''));
      errs = 0;
      if (resp.get_updates_buf) { cursor = resp.get_updates_buf; saveCursor(cursor); }
      for (const m of (resp.msgs || [])) dispatch(m).catch(e => log('dispatch错误', e.message));
    } catch (e) { errs++; log('轮询错误(' + errs + ')', e.message); await new Promise(s => setTimeout(s, errs >= 3 ? 30000 : 2000)); if (errs >= 3) errs = 0; }
  }
})();
```

## 附录 B：iLink Bot API 速查（开发者排错用）

| 端点 | 方法 | 用途 |
|------|------|------|
| `/ilink/bot/get_bot_qrcode?bot_type=3` | GET | 拉登录二维码，返回 `qrcode`(id) + `qrcode_img_content`(链接) |
| `/ilink/bot/get_qrcode_status?qrcode=<id>` | GET | 轮询扫码状态：`wait`/`scaned`/`confirmed`/`expired`。confirmed 时返回 `bot_token`/`ilink_bot_id`/`ilink_user_id` |
| `/ilink/bot/getupdates` | POST | 长轮询拉消息，请求体带 `get_updates_buf`(游标)，返回 `msgs[]` + 新游标 |
| `/ilink/bot/sendmessage` | POST | 发消息（文字/图片/文件，靠 item type 区分：1文字 2图片 3语音 4文件） |
| `/ilink/bot/getuploadurl` | POST | 发图/发文件前换上传地址（media_type：1图 2视频 3文件） |

- **鉴权头**：`AuthorizationType: ilink_bot_token` + `Authorization: Bearer <bot_token>` + `X-WECHAT-UIN: <随机base64>`
- **CDN**：`https://novac2c.cdn.weixin.qq.com/c2c`，下载 `/download?encrypted_query_param=`，上传 `/upload?encrypted_query_param=&filekey=`，媒体走 **AES-128-ECB** 加解密
- **消息类型**：`message_type` 1=用户发来 2=机器人发出；语音的转写文字在 `voice_item.text`；引用消息在 `item.ref_msg.message_item`
- 本协议参考自开源项目 cc-weixin（qufei1993/cc-weixin）的 API 文档，本手册的桥接是据此**自主实现**、不依赖该插件。
