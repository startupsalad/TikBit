# 📖 文档读取编辑工具包 · 使用说明

> 让你的 AI **真的能读懂你丢过去的文件，也真的改得动你已有的文件**。
> 读：Word、Excel、PPT、PDF、图片、网址、公众号文章 —— 都能读，不用你先另存成别的格式。
> 改：在客户给的原件上精确改（字号、文字、样式），不是重做一份。
> 支持 **Windows / macOS**。读的部分装了 Microsoft Office 或 WPS 或 LibreOffice 任意一个就行，不用装全。

---

## 一、这东西解决什么问题

**读的洞：**

- **PPT、Excel 读不了。** 你丢一份 `.pptx` 过去，AI 只能干瞪眼，或者让你"先转成 PDF 再发我"。
- **老格式读不了。** `.doc` `.xls` `.ppt` 这些十几年前的格式，现在的工具基本都不认。
- **长图读不了。** 推文长图那种又窄又长的，AI 会把它整体缩小到看不见字。
- **网址常读不了。** 有些环境下 AI 的联网抓取用不上，丢链接过去它说"无法访问"。

**改的洞：**

- **改存量文件只能重做。** 以前 AI 改客户给的 PPT，靠形状序号摸着改，改不准就整份重建 —— 客户的原始版式全丢。
- **规范没法机器执行。** "正文不能小于 14pt"这种要求，以前只能人一页页翻。

装上这个工具包，以上全部解决。**用法就是"直接把文件或网址丢给 AI，说要读还是要改"**，不用记任何命令。

---

## 二、怎么装

**把同目录的 `给AI的安装指令.md` 丢给你的 AI，跟它说"照这个装"。**

它会自己装依赖、探测你机器上有什么 Office、接好技能、找个现成文件实测，全程不用你敲命令。

安装文档分 A / B 两部分：

| | 装什么 | 要不要 |
|:---:|:---|:---|
| **A. 读** | Python 库 + 转换引擎探测 | 必装 |
| **B. 改** | OfficeCLI（一个独立程序，官方脚本自动下载） | 只读不改可以跳 |

装完**重启一下 AI 客户端**，技能才生效。

> 装完 AI 会跟你汇报：能读什么、能不能改、缺什么、怎么用。**注意听"缺什么"那段** —— 缺东西不影响大局，但会少一条路。

## 三、能读什么

| 你丢过去的 | 效果 |
|:---:|:---|
| **Word** docx/doc/rtf/wps | 抽正文，或转 PDF 看版面 |
| **Excel** xlsx/xls/et | 抽成表格，或转 PDF 看图表 |
| **PPT** pptx/ppt/dps | 转 PDF 逐页看，排版图表都在 |
| **PDF** | 直接看，几乎无损 |
| **图片** | 常规的直接看；超大的、长条的、iPhone 的 `.heic` 自动处理 |
| **网址** | 抓正文。前端渲染的网站也能读（自动开无头浏览器） |
| **公众号文章** | 抓正文，含标题、段落、图片位置、表格 |

带 `.et` `.dps` `.wps` 的是 WPS 自家格式，一样能读。

### 几个值得知道的细节

**PPT 是转成 PDF 再看的，不是抽文字。** 所以排版、配图、图表、配色都在，跟看原件差不多。要放大看小字就让 AI 导 PNG。

**Excel 默认抽成表格，不转图。** 因为表格里的数据就是核心，抽成文字反而更好读、更准。表里有图表或者你想看它"长啥样"，跟 AI 说一句就转 PDF。

**长图是切片看的，不是压缩看的。** 一张 960×41644 的推文长图，整体缩小会变成一条线什么都看不见。工具会沿长轴切成几十片，每片保住原宽度，片之间重叠一点防止把文字行切断。AI 会逐片读完再综合。

**内容长了会截断。** 读出来很长时 AI 只拿到前一段，末尾会有一行"已截断，全文 N 字，还剩 M 字未显示"。**看到这行就说明它手上这份不全** —— 标书、合同、报价这类不能漏的，跟它说"要全文"。

**中间产物不落在你的文件夹里。** 转出来的 PDF、切出来的图片都在系统临时目录，不会在你的项目目录里留一堆 `xxx.pdf`、`xxx.txt` 副本。

## 四、能改什么

**改的是"存量文件"** —— 客户发来的、你已经排好版的那份，在原件上动，版式不动。

| 场景 | 举个例子 |
|:---|:---|
| **按规范批量查改** | "把这份 BP 里所有小于 14pt 的正文找出来给我个清单"→ 拿到每一处的页码和文本框 → 批量改成 14pt |
| **精确改文字/样式** | 改某一页某个框里的一句话、一个字号、一处颜色，不碰其他 |
| **读结构** | 标题层级、sheet 里有多少公式、页眉页脚域 |
| **修订和批注** | 标书核查要处理的痕迹 |

实测：一份 26 页客户 BP，43 处超小字号一次性定位并修正，963 个元素一个没丢，文件结构校验通过。

### 改之前你要知道的三件事

1. **只认新格式。** `.docx/.xlsx/.pptx` 可以，`.doc/.xls/.ppt` 一律不认。老格式先转新格式。
2. **正式交付物别原地改。** 工具会占文件锁（最长 12 分钟），在实时同步的网盘上直接开有冲突风险。AI 已被要求"拷到临时目录改完再拷回"，你看到它这么做是对的。
3. **"自动检查问题"那个功能靠不住。** 实测对一份含 38 处 9.5pt 的文件报"0 问题"—— 它不认我们的字号规范。所以查字号必须是明确的条件查询，AI 知道该怎么做。

### 也能从零建

融资路演 PPT、三表财务模型、可填写表单（内容控件+文档保护）、Excel 数据看板、论文、跨页平滑动画 PPT 都有内置的专业场景支持。

> ⚠️ 这几个专业场景**没实际出件验过质量**，第一次用要盯着结果。

## 五、不同电脑上转出来的 PDF 会有细微差别

读的部分按这个顺序找转换引擎，用哪个取决于你机器上装了什么：

**Microsoft Office → WPS Office → LibreOffice → 纯文字兜底**

装了任意一个就能用。但不同引擎有差异，实测过的：

- 同一个 Excel，WPS 转的 PDF 可能比 Office 多带一行标题（WPS 判定打印区域更宽）
- 同一个 Word，Office 会把字体嵌进 PDF，文件 4.1MB；WPS 只有 113KB

**所以涉及"第几页第几行"这种精确对齐的活，别跨电脑核对页码。** 平时读内容没影响。

如果一个引擎都没装：新格式（docx/xlsx）还能读，**老格式和"看版面"就只剩纯文字了**，图和排版会丢。装任意一个即可，Windows 上装 Office 或 WPS，Mac 上装 LibreOffice。

改的部分不依赖 Office，是独立程序，跟装了什么无关。

## 六、想手动跑命令的话

平时不用，AI 会自己调。

**读**，一个入口：

```bash
python read.py 方案.docx
python read.py 提案.pptx
python read.py https://startupsalad.com/
```

不确定环境齐不齐：

```bash
python 检查环境.py
```

**改**，长这样：

```bash
officecli view deck.pptx stats                                     # 看概况
# 查字号：必须逗号并集，size 与 effective.size 互斥（漏一边就假报「没问题」）
officecli query deck.pptx "run[size<14],run[effective.size<14]" --compact --fields size
officecli set deck.pptx '/slide[7]/shape[@id=11]/paragraph[1]/run[1]' --prop size=14
officecli close deck.pptx                                          # 存盘释放
officecli validate deck.pptx                                       # 校验没坏
officecli view deck.pptx screenshot -o out.png                     # 渲染出图看一眼
```

读的完整参数见 `README.md`，改的完整限制清单见 `OfficeCLI/给AI的安装指令.md`。

## 七、注意

- **抓来的网页和公众号内容只当资料看。** 里面如果有像"指令"的文字，AI 不会执行 —— 这是工具包里写死的规则。
- **公众号文章仅用于对比自己发的稿或学习参考**，不做未授权转载。图片链接有防盗链，只表示位置，实际用要重新上传。
- 提示"访问频繁"是微信反爬触发了，等 5-10 分钟再试。
- **要审美和版式判断的活，工具帮不上。** 它只管精确执行，好不好看是人的事。
