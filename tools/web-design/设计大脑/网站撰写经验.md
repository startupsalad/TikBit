# 网站撰写经验（营销型官网 / 落地页）

> **用途**：做营销型网站（官网、产品落地页、转化页）的**通用经验与避坑**，未来做任何网站先读这份，不重走弯路。
> **触发场景**：写/改任何对外营销网站、落地页、产品介绍页；做网页文案；做网页视觉与排版；导出网页长图/PDF 时。

---

## 一、文案策略（怎么写打动客户的网页文案）

### 1.1 首屏定生死：5 秒内让人 get 到「是什么 + 核心卖点」
- 用户不会细读每一处。**首屏（不滚动就看到的部分）必须让人立刻明白：这是什么服务 + 最核心的 1-2 个卖点**。
- 服务名（中英文）要**足够明显**，不要缩在角落小字里——客户得一眼知道点进来的是什么。
- 核心卖点用**徽条/双柱卡片**钉在首屏或首滚动位，别埋在页面中段（埋了等于没有）。

### 1.2 主打「价值」与「划算」，不主打「最便宜」
- 一味渲染"免费/最便宜"会招来纯比价用户、还让人误以为核心产品也廉价 → 反而损害信任。
- 正确姿势：**该花的钱客观讲清，不该花的明确说不收**；强调"花得值/划算/把钱花在刀刃上"，而不是"全网最低"。
- 用"成本合理/同样的钱办更多事"替代"更便宜"，吸引看重价值的客户而非只追低价的客户。

### 1.3 措辞要专业、务实，像顾问而非推销员
- 给企业/专业客户看的内容，要**专业、严谨、克制**。每条卖点落到"业务结果"（解决什么经营问题），而不是"操作动作"或口号。
- 反例（轻浮）：「张口即来」「接得住跟得紧」「搭把手」。
- 正例（务实）：「把重复性人工从核心岗位上剥离」「让成交经验可复制、不依赖个别能人」「降低人员流动带来的损失」。
- 数字要可信不夸张（如"2 天→半天""单篇 2 小时→20 分"），删掉"翻倍""5-6 倍"这类容易引人怀疑的口号式表达。

### 1.4 真实案例 > 空话承诺
- 别写"不是 PPT 上的承诺"这类自我辩解，直接讲"这些是我们亲手做出效果、引以为豪的真实案例"。
- 案例用「具体行业 + 具体场景 + 具体数字」，不空谈。

### 1.5 体系感：一组并列内容要"同构"
- 多个并列板块（如"能帮你做什么"的 N 个维度），**命名格式、排版结构、文字长度都要统一**，让人感觉是"一个体系下的 N 个子项"，而不是零散堆砌。
- 推荐格式：「名字 · 一句话价值」标题 + 3 条「子项：说效果」。控制在 4-6 个，太多客户看不过来。
- 维度命名别平庸（「方案文档」← 平淡 →「方案智写」← 更抓人）。

### 1.6 CTA / 转化路径
- 按钮要跳到真正的转化入口（如咨询页、加联系方式），别只做页面内滚动。
- 转化步骤按"低门槛→高承诺"排：先聊一聊（免费咨询）→ 免费体验/诊断 → 正式合作。

## 二、视觉与排版（保持高级感、不土）

### 2.1 配色：主色只做强调，别大面积铺
- 品牌主色**只用于强调**（标题渐变、按钮、徽标、眉标），不要大面积铺满——大面积纯色不高端。
- 底色用白 / 浅色（浅灰、浅色渐变交替分区）。**底部联系区/重点条用深黑高级底 + 主色光晕**，形成收尾的分量感。
- 一组并列卡片可各配一种专属辅助色（青蓝 `#1e6fd9` / 姜黄 `#e8820c` / 墨绿 `#2e8b57` / 紫 `#7c3aed` 等），区分维度又不杂乱——但整体仍统一在一套色系里。

### 2.2 字号与间距：同一区块内节奏要统一（最常见的"乱"源）
- **大标题（H1）多行时，每行字号必须一致**——两行一大一小是"显得歪/乱"的头号原因。
- 同一屏内各元素（徽标 / 标题 / 副标题 / 卡片）的间距要**递进协调**，别忽大忽小。
- 标题尽量**控制在一行**，能不换行就不换行；副标题适当收窄宽度（如 `max-w-2xl`）让换行更自然。
- 文案太长会被迫折成两行、显得拖沓 → 主动精简。

### 2.3 统一的设计语言（一个站内所有页面必须一致）
- 字体：标题用品牌展示字体、正文用干净无衬线（思源黑体等）、小标签/数字用等宽字体（JetBrains Mono）。
- 统一元素：粒子背景、主色光晕、网点纹理、眉标、卡片 hover 效果、滚动渐入。
- 新页面/新板块必须**复刻现有设计系统**，不另起一套风格。

### 2.4 动效：点到为止、可降级
- 背景动效（如光晕/晕染）做"若隐若现"的氛围感即可，**透明度峰值压低**（如 0.16），是背景不是主角。
- 多个动效元素**错开节奏和延迟**，别整齐划一地同步（呆板）。
- 详见 §3.3 移动端性能。

## 三、技术与导出避坑

### 3.1 改动流程（每次必走）
1. 大组件（如整页 React 文件）用 Write 建骨架 + 占位符，再用 Edit 分段填充。
2. 改完**必跑** `npx tsc --noEmit -p tsconfig.json` 验证无类型错误，再打包。
3. 删内容后注意清理**未使用的 import**（否则 tsc 报错）；改按钮交互后清理废弃的辅助函数。
4. 部署三步：服务器先备份 → `rsync` 上传 dist → reload 服务；部署后 `curl` 抓线上 bundle 关键词确认新文案已上线。

### 3.2 中文路径坑
- Bash 里 `cd` 进项目目录用 `$HOME` 开头的绝对路径（中文路径直接写易出错）。
- Edit/Read 工具的文件路径优先用相对路径或绝对路径。

### 3.3 移动端性能（大部分用户用手机看）
- **SVG 滤镜动画（feTurbulence 湍流 + feDisplacementMap 实时重算）在手机上是 CPU 杀手**，是滑动卡顿的主因。
- 解法：手机端（`max-width:768px` 或 `prefers-reduced-motion`）**关掉最贵的滤镜动画，保留 CSS 的 opacity/transform 动效**（GPU 合成、很轻）——视觉几乎无损，卡顿大幅缓解。
- 排版用响应式类（`flex-col sm:flex-row`、`md:grid-cols-2`）确保手机端自动堆叠成单列。**改完务必想着手机端怎么显示。**

### 3.4 长图 / PDF 导出（踩过的坑，重复踩=白干）
- **网页字体（尤其 Google Fonts 中文如思源黑体）大概率嵌不进导出图**，会回退系统字体 → 字宽变化 → 文字重排溢出重叠。
  - 解法：截图前把容器**强制改成系统字体栈**（PingFang SC 等）+ 传 `font:{cssText}` 统一，截完还原。
- **html2canvas 对 CSS Grid 和圆/药丸内文字垂直居中不可靠** → 序号 badge 偏位、多列塌成单列。优先用 `modern-screenshot`（foreignObject 真实渲染）。
- **长图按桌面视口渲染**（`windowWidth:1280`，命中 lg: 断点走桌面多列布局），别按手机宽度（会塌成单列、被压扁）。截图宽度跟着内容容器走。
- 渐变文字导出会变透明 → 导出前转实色。
- PDF 用浏览器原生打印（`window.print()` + `@media print`）：矢量文字、`break-inside:avoid` 智能分页，优于截图。

### 3.5 视觉效果别自己反复跑 headless 脚本验证
- AI 环境看不到真实渲染，间接量 DOM 几何会绕圈、费 token 又测不准。
- 正确节奏：根因查清 → 最小改动 → tsc/build 不报错 → 部署 → **让用户看实际产物**。视觉对不对最终靠肉眼，交给用户一秒判断。
