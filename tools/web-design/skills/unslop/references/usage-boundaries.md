# 项目执行边界

在既有项目中使用 unslop 时，以这些边界及用户项目规则为准；上游审美建议与参考参数不覆盖品牌或业务要求。

- **品牌与组件优先**：先读项目品牌和设计系统，保留正式 Logo、字体、色板、字重、区块与组件。没有品牌时才提出方向；不因上游偏好低字重或大图首屏而推翻有效规范，不把客户品牌套成 TikBit。
- **范围和严重程度**：先列位置、问题、影响与方向。仅诊断时不改代码；用户已授权且方向明确的本地修改可继续，新增品牌改向、功能或付费范围再问。重度按九层检查，轻度只修命中项；无明显问题不强改，九层不要求每层都有修改。
- **业务与数据保护**：保留导航、区块顺序、路由、事件、表单、登录及数据源。金额、时间、精度和统计口径不变，不以更像真的数字替换真实数据。无依据的宣传数字标待核实，不自行编造或删有效信息。合成测试数据只放隔离样例，说明放产品画面外。
- **局部样式**：复用变量和组件，避免全局覆盖；验收直接受影响的其他页面。
- **素材和费用**：先用已有素材、真实产品内容、图表或代码。只有用户明确要求生成图片或视频才调用工具，遵循已确认型号、数量和费用范围；失败不自动重发付费生成，Logo 不用模型重画。
- **回退和临时目录**：改前保留可回退版本。快照、截图、帧及测试放当前环境的独立任务临时目录，正式交付物放所属项目，重名不覆盖。上游 unslop/、unslop-story/ 只是示例路径，不默认建在知识库根目录；按所在环境规则收口本任务文件和进程。
- **网址和快照**：用当前可用读取工具获取网页，需要视觉再在本机浏览器看。snapshot.mjs 只生成静态副本并移除脚本，登录交互、动画与跨域素材可能丢失；--dark 插入 color-scheme 可能改变原生控件。先比原页与副本，不承诺完整还原或已改线上；有源码优先改源码，私密页与截图不发外部服务。
- **实际验收**：桌面和手机实际渲染，核裁切、溢出、焦点、对比度、减少动态效果偏好、导航、表单、弹窗及真实数值。按问题做足回归，不受上游最多三次渲染的效率建议限制。没运行的项目明确说明，不把文件存在当通过。
- **按需依赖**：诊断和改稿复用宿主能力；snapshot.mjs 另需 Node.js、Playwright 或 playwright-core 与浏览器，story.mjs 另需 ffmpeg。先复用宿主运行时，必要时仅在当前进程设置 NODE_PATH、CHROME_PATH；不把本机路径写入共享规则，不把 Skill 已安装说成脚本依赖齐备。
- **录制与发布**：用户明确需要才评估录制。story.mjs 会清理固定 .story-frames 并覆盖指定视频，执行前复核、限定无旧文件的任务目录并确认输出、依赖及进程收口。网站上线另守授权、备份、预览和回退流程；本地改稿不等于发布。安装后优先开新对话，不保证旧对话自动重载。
