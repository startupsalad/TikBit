# 知识库格式说明

后端启动时会自动读取本目录下所有 `.md` / `.txt` 文件，按文件名排序拼接，作为客服助手的回答依据。

## 怎么组织内容

1. **FAQ 问答对最好用**：一问一答，命中率最高。参考 `kb.example.md` 的格式。
2. **一个主题一个文件**：如 `产品介绍.md`、`常见问题.md`、`售后政策.md`，方便维护。
3. **控制总量**：所有文件加起来建议 ≤ 1 万字（约 20000 字符）。超出会被截断并在日志告警，也会拖慢响应、增加成本。
4. **纯文本为主**：不需要 HTML/复杂排版，Markdown 标题 + 列表 + 表格足够。

## 更新知识库

改完本目录文件后，**重启后端服务**即可生效（知识库在启动时加载一次）：

```bash
# Docker 部署
docker compose restart chatbot
# 直接 node 运行
# Ctrl+C 停掉后重新 npm start
```

## 提高回答质量的技巧

- 把客户真实问过的高频问题整理成 FAQ，比堆产品手册管用。
- 答案写得简洁、口语化，助手会照着这个风格回答。
- 明确边界：不希望它答的（比如报价、竞品对比），在知识库里写清楚"这类问题请联系人工"。
- 标注权威信息来源和更新时间，避免它拿旧数据乱答。
